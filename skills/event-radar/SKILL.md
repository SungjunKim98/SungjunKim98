# 앱테크 이벤트 레이더 (event-radar)

일회성 마케팅 이벤트는 **빨리 알면 이기는 콘텐츠**다. 오픈 직후 정리 글이 검색 상단을 먹고, 마감 하루 전 글은 아무도 안 본다.
이 스킬은 "감지 → 검증 → 저장 → 글/일정 생성"을 한 번에 돌린다. 데이터와 렌더링은 저장소의 `radar` 파이썬 도구(표준 라이브러리만 사용)가 담당한다.

## 0. 원칙 (생략 불가)

1. **사실만 쓴다.** 혜택 금액·기간·조건은 공식 공지/앱 화면/언론 보도 중 하나 이상에서 확인된 것만 넣는다. 출처 URL은 `sources`에 반드시 남긴다.
2. **연도를 확인한다.** "토스 행운퀴즈 정답 (11월 25일)" 같은 기사는 제목에 연도가 없다. 작년 기사를 올해 이벤트로 착각하지 않도록 기사 발행일을 반드시 확인하고, 확인이 안 되면 등록하지 않는다.
3. **링크는 공식 도메인만 싣는다.** `python -m radar check <url>`에서 `official`이 아닌 링크는 본문에 하이퍼링크로 넣지 않는다 (렌더러가 자동으로 막아준다). 문자/DM으로 도는 "혜택 링크"는 스미싱 대표 수법이라, 글에는 항상 "앱에서 직접 진입" 경로를 같이 적는다.
4. **추천인/초대 링크를 본문에 넣지 않는다.** 내 리워드용 초대 링크는 광고 표기 없이 넣으면 표시광고법 문제가 될 수 있다. 넣을 거면 사용자 승인을 받고 "추천인 링크 포함" 문구를 명시한다.
5. **퀴즈 정답 글은 정답만 쓰지 않는다.** 정답 나열 글은 언론사가 이미 독점하고 있다. 우리 글의 가치는 "여러 이벤트를 마감순으로 한 장에 모아 주고, 몇 분이면 끝나는지와 놓치지 않을 일정까지 알려주는 것"이다.
6. 발행(공개 게시)은 사용자 승인 후에만 한다. `cheomji-newsroom`의 발행 규칙을 그대로 따른다.

## 1. 감지 (WebSearch, 병렬로 한 번에)

아래 쿼리를 **같은 턴에 병렬로** 던진다. `{월}`, `{년}`은 오늘 기준으로 바꾼다. 결과가 부실하면 그 쿼리만 `extended`로 재검색한다.

| 플랫폼 | 쿼리 |
|---|---|
| 토스 | `토스 이벤트 {년} {월}`, `토스 행운퀴즈 정답 {월} {일}`, `토스 선착순 포인트 지급`, `토스 친구 초대 이벤트 {월}` |
| 카카오페이 | `카카오페이 이벤트 {월} {년}`, `카카오페이 노난날`, `카카오페이 포인트 선착순`, `카카오페이 퀴즈 정답` |
| 네이버페이 | `네이버페이 이벤트 {월} 적립`, `네이버페이 포인트 선착순 {년}` |
| 공통 | `앱테크 이벤트 {월} 정리`, `{월} 선착순 혜택 마감`, `간편결제 캐시백 프로모션 {년} {월}` |

감지 대상 판별:
- ✅ 기간이 정해진 일회성/단기 이벤트 (오픈일·마감일이 있음), 선착순/예산 소진형, 공유·초대 링크형, 퀴즈형
- ❌ 상시 혜택(기본 적립률), 이미 마감된 것, 카드사 단독 이벤트(플랫폼 무관), 출처가 커뮤니티 글 하나뿐인 것

공식 페이지(toss.im, kakaopay.com 등) 접근이 네트워크 정책으로 막히면 언론 보도로 대체하되 `verified`는 `false`로 두고, 사용자에게 "앱에서 확인 필요" 목록으로 따로 보고한다.

## 2. 저장

감지한 이벤트를 JSON 배열로 만들어 저장한다. 스키마는 `data/example-events.json` 참고.

```bash
python -m radar add --json /tmp/새이벤트.json      # 같은 이벤트는 id로 중복 제거되고, 새 정보만 덮어씀
python -m radar check https://toss.im/... --platform toss
python -m radar list                               # 마감 임박순, 🔥=48시간 내 마감, ⏳=오픈 예정
```

필드 작성 요령:
- `end`: 날짜만 알면 `"2026-11-30"` (자동으로 23:59 처리), 시각까지 알면 `"2026-11-30 18:00"`
- `first_come`: 선착순·예산 소진 시 조기 종료 문구가 있으면 `true` → 일정표가 "오늘 참여"로 바뀐다
- `effort_min`: 참여에 걸리는 시간. 독자가 "할까 말까"를 정하는 핵심 정보라 가능하면 꼭 채운다
- `tips`: 실제로 차이를 만드는 것만 쓴다 (예: "오픈 시각 정각보다 1~2분 뒤가 덜 막힘" 같은 건 근거 있을 때만)

## 3. 글 생성

| 상황 | 명령 | 글 형태 |
|---|---|---|
| 혜택이 큰 단일 이벤트가 새로 떴을 때 (속보형) | `python -m radar post <id> --out out/post-<id>.md` | 한눈에 보기 표 → 참여 방법 → 꿀팁 → 주의점 → 일정표 |
| 주 1~2회 정기 글 | `python -m radar roundup --out out/roundup.md` | 마감 임박순 요약표 → 이벤트별 카드 |
| 독자 배포용 일정 | `python -m radar ics --out out/events.ics` | 마감 하루 전/3시간 전, 오픈 10분 전 알림 |

생성된 초안은 뼈대일 뿐이다. 이후 `cheomji-newsroom`의 5단계(코미디언) → 7단계(마무리 작가: 제목·첫 문장·해시태그·컴플라이언스)를 그대로 태운다. 초안에 있는 `[편집 메모 — 발행 전 삭제]` 줄은 마무리 단계에서 반드시 해소(검증 후 삭제)한다.

제목 패턴 예시:
- 속보형: `[D-3] 토스 ○○ 이벤트, 3분이면 ○○원 — 마감 전에 이것만 챙기세요`
- 모음형: `11월 첫째 주 놓치면 아까운 앱테크 이벤트 7개 (마감순)`

## 4. 정리

- 발행 후 `python -m radar prune`으로 마감된 이벤트를 `data/archive.json`으로 옮긴다. 아카이브는 "작년 이맘때 이런 이벤트가 있었다 → 올해도 할 가능성" 같은 예고 글 소재가 된다 (예: 연말 결제 프로모션, 블프 시즌, 설·추석).
- 반복 실행은 `/loop` 또는 예약 작업으로 걸어두면 된다 (예: 매일 오전 7시 감지 → 신규 있으면 알림, 매주 월요일 모음 글 초안).
